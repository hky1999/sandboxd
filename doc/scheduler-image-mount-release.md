# 镜像挂载路由与清理失败的原归属保留

沙箱守护进程 sandboxd 的镜像挂载入口（`pkg/imagemanager/api/http.go`）、Nydus／S3 daemon 管理器（`pkg/imagemanager/distillfs/`）和 OCI 镜像管理器（`pkg/imagemanager/oci/`）保留未完成清理的原记录。上层文件系统管理器（`internal/server/fsmanager.go`）的来源登记和完成记录不能补出底层已丢失的路由、PID 或挂载身份；底层错误必须返回给原所有者，不能转换成已经释放的结果。

## 根目录所有权与关闭

镜像管理模块（`pkg/imagemanager/module.go`）在准备目录、读取旧登记或打开数据库之前取得镜像根目录的独占文件锁 `.scheduler-image-manager.lock`。锁文件必须是当前用户拥有、权限为 0600、只有一个硬链接的空普通文件，打开时拒绝符号链接。根目录需要当前用户拥有且禁止其他用户写入；可写测试子目录只有在原直接父目录为当前用户独占的 0700 目录时才接受。操作准入和最终进程派发重新核验原目录及锁文件的设备、inode、权限和所有者，父目录例外也重新核验。不同根目录可以独立使用，同一根目录的另一个管理器在任何恢复或暂存清理之前拒绝。锁文件不自动删除。

每个已准入的原操作持有目录所有权，异步初始化也独立持有。最终进程启动在原物理状态锁内重新核验身份，并在目录所有者锁下检查关闭状态；拒绝旧所有者不补造 Start 系统调用失败或未派发证明。关闭先停止准入和后台重试；镜像 API 等待全部已准入请求退出后关闭挂载数据库，OCI 管理器等待缓存维护及解包工作结束后关闭。模块的独立所有权一直保留到两个后端完成关闭，防止在途操作结束前交给新管理器。`CloseWithContext`／`StopWithContext` 超时只返回尚未关闭，后台继续排空并保留文件锁和数据库；不能把超时当成退役成功。

此锁协调同一文件系统上合作使用相同根目录的管理器，不承诺跨宿主租约、主机断电持久性或管理员强制替换目录后的隔离。未绑定分配归属、完整部分启动出生对账、普通 OCI 物理身份及整个沙箱退役证明仍须独立完成；取得或交出目录所有权都不授权归还预算。

## 路由发布与移除

配置了持久挂载路由数据库时，`MountOCI` 与 `UnmountOCI` 对同一个原 image URL 串行执行；不同来源分别使用自己的锁。数据库读写错误、缺失路由、未知后端和不完整记录都会返回错误，卸载不会转到另一个后端寻找替代资源。只有原路由明确指定 Nydus 或 OCI，才会调用该后端。

挂载成功后的路由写入失败必须返回错误，不触发内联卸载。上层调用前已经保存的来源意图继续保留，用于对账原调用及其可能的物理副作用。已有路由与新发布的五个字段（包含原物理代际）不同时，原记录继续保留，不能由新的挂载结果覆盖。

卸载后端返回错误时保留原路由。后端成功后，在同一个数据库事务中比较原 `ImageURL`、`MountType`、`NydusImageURL`、`MountPoint` 和 `PhysicalGeneration`，保存绑定原来源及代际的完成记录并移除仍完全匹配的活动记录；记录变化、损坏或缺失都返回未知错误。具有原代际的释放必须携带该代际；不能从当前路由采用替代执行的身份。没有配置路由数据库时保留明确的旧模式；数据库运行中损坏或缺失记录不会进入该模式。

## Nydus 和 S3 daemon 清理

`Unmount` 在 daemon 生命周期锁内设置未确认释放状态。初始化仍在推进、进程报告存活但 PID 无法取得、停止观察超时、卸载失败、挂载回读失败或 PID 文件移除失败，都保留原 PID／登记和未完成状态。新挂载不能复用该 daemon；原所有者可以重试清理。

卸载目标使用内核挂载表的完整目标路径查询，能识别设备编号与父目录相同的 bind mount。未知挂载状态返回错误。成功的卸载系统调用后再次查询挂载表；目标仍存在或观察失败时不清除 PID。Nydus／S3 将成功调用标记写入原物理登记，后续重试及重开继续确认原目标消失，不重复卸载一个随后出现的目标。目标路径必须是绝对规范路径，不能用符号链接充当目标。

只有停止观察、挂载消失与 PID 文件移除均成功，daemon 才进入停止状态并清除未确认释放状态。挂载入口只在成功卸载后清除来源的已引用标记。显式清理、过期清理、失败挂载清理和磁盘压力清理都保留清理失败的 daemon 及其保存文件；挂载确认或目录移除错误不会变成成功清理。

## Nydus 和 S3 的原物理登记

在启动进程之前，`physical_identity.go` 保存随机物理代际、宿主 boot ID、当前线程的挂载与 PID namespace 的设备号和 inode、绝对目标路径、独立 `pid-<generation>` 文件路径、程序及完整 argv 的 SHA256，以及配置和 Nydus bootstrap 内容的来源摘要。启动后保存 PID、内核进程启动时间、实际程序及 argv 摘要；挂载就绪后保存挂载表身份和内核 `STATX_MNT_ID_UNIQUE` 唯一挂载 ID。来源摘要固定实际配置与 bootstrap 字节，尚不是解析后的 registry manifest digest。

原记录依次处于 `launching`、`running`、`releasing` 和 `released`；启动系统调用明确失败使用 `not_started`。同一代际的启动条件及已知出生身份不能替换或清除，迟到的启动事实不能把清理阶段改回运行，已经确认的卸载成功不能回退。完成状态发布失败时保持待发布状态；同代际重试仅同步原记录，成功后才能回放完成，不重新观察或清理替代目标。待发布状态没有解决前不能创建新代际。

最终进程启动由 `original_dispatch.go` 执行，与释放意图发布共用原物理状态锁。它重新核验原代际、阶段、目标、独立 PID 文件、boot／namespace、完整 argv、实际程序和来源字节摘要，然后在同一把锁内调用 `Start`。释放先取得该锁时，即使尚无原出生事实，也先保存 `releasing`，再返回未知；后台初始化不能随后启动进程。释放记录的持久同步未确认时也阻止启动。启动先取得该锁且成功，但出生事实还未保存时，清理仍返回未知，不能假定未开始或已经退役。

只有实际 `Start` 返回错误才保存 `not_started` 与 `no_dispatch_confirmed=true`；身份检查错误、缺失出生事实或空库存都不补造这一证明。该证明在转入 `releasing`、释放失败、重开和最终释放时单调保留，且不能与进程、挂载或成功卸载事实并存。schema 1 新增可选布尔字段，false 时省略，不改变旧记录的规范摘要；旧 `not_started` 登记在推进释放时保留原明确失败事实。旧严格读取器会拒绝含新字段的记录，不能降级运行程序后忽略该字段。进程内锁与本地受控检查仍不提供跨进程隔离、独立部分启动对账、有界系统调用或主机故障下的完整验收。

原进程信号核对 boot／namespace、PID、启动时间及程序和 argv，再打开并核对 PID 句柄，使用 `pidfd_send_signal`，不退回对数值 PID 发信号。卸载前在原所有者锁和固定线程内核对完整挂载身份及来源；卸载后独立确认目标不存在。唯一挂载 ID 或 PID 句柄不受支持、观察未知、原来源改变或 PID 已复用时返回错误，保留原归属。完成回执目前限于这个 daemon 保存记录的原代际；换代或删除后的完整历史回执仍需上层持久契约。

`daemon_metadata.go` 以 0600 临时文件、文件同步、rename 和目录同步发布最多 1 MiB 的 schema 1 元数据，发布前核对此前原文件的完整字节摘要。拒绝符号链接、非普通文件、记录替换、超长记录、未知或重复字段、尾随对象及完整性错误。管理器先验证全部登记，再启用任何恢复 watcher；损坏登记不能通过日志警告被忽略。目录为 daemon 私有所有者目录，字节比较不提供跨进程文件系统原子条件替换，摘要不是签名，也不能隔离过去完整有效快照的回滚。

重开保留 `releasing` 和成功卸载标记。没有原出生身份的旧登记以及没有原进程出生结果的 `launching` 登记保持未解决，不能采用当前 PID／挂载来补归属。独立迁移和部分启动对账尚待实现；本地原子发布测试不等于断电持久性验收。

## 独立原进程及挂载身份记录

新启动意图在主元数据的物理身份中保存 `birth_protocol=1` 及原 daemon 工作目录的设备号和 inode；这两个字段在同一代际中不可修改。缺省协议为 0，字段省略时保留旧 schema 1 的规范编码和摘要；旧记录不自动升级。旧严格读取器拒绝新字段，因此必须匹配升级，不能降级后忽略字段。

`birth_evidence.go` 在已经观测并核验原进程后先保存 `<daemon-directory>/physical-birth-<generation>-process.json`，在原进程和原 FUSE 挂载均核验后先保存同目录的 `physical-birth-<generation>-mount.json`，随后才提交主元数据。挂载记录必须关联已经独立保存的同一原进程。记录只含 schema、daemon ID、类别、原启动身份、进程及挂载身份和完整性摘要，不含后端配置、凭据或原始 argv。每项最多 8192 字节，权限为 0600，没有自动回收；完整性摘要不是签名，也不隔离具有写入权限者替换完整有效快照。

读写先打开并核对原目录设备号、inode、所有者及禁止其他用户写入的权限，随后全部文件操作相对该目录句柄进行。发布使用独占临时文件、文件 fsync、不能覆盖现有名字的 link、移除临时名字及目录 fsync。相同字节重试只同步原记录；不同原身份、损坏文件、符号链接、额外硬链接、非普通文件、权限变化及超限均拒绝。独立发布失败不会提交主元数据或伪装成已经保存身份；已可见但目录同步失败的记录保留，明确清理再次同步后才能采用。

显式原代际清理先持久保存 releasing，随后严格读取原身份文件并比较原操作关联的代际、启动作用域、原目录、原来源和已有主元数据身份。主元数据缺失的身份只能从这一原记录补交，补交的主元数据持久确认之前不发送信号、不卸载或删除 PID 文件；不会通过当前 PID 或当前挂载推断出生。补交不重新派发、不返回 ready、不打开来源引用、不取消 releasing。已经完成的原释放先回放原主元数据，不读取替代工作目录或当前执行。独立查询仍只读，不自动补交记录。

没有原进程事实的成功 Start 仍为未知，不能补造未派发证明。原进程已知且确认不存在时，没有挂载事实仅能在目标确认为空的条件下继续原清理；目标已有挂载时不能采用这个当前挂载。当前 PID 复用、原作用域或来源变化、挂载被替换、事实缺失或矛盾都保留原清理状态。这些记录不解决成功 Start 到首次身份保存之间的窗口，也不提供启动确认、跨宿主隔离或断电验收。其他来源完成历史、普通 OCI、整个沙箱退役、节点预算结算、有界调用和安全回收仍待完成；本地受控文件失败与恢复测试不能替代 BareMetal1 物理故障验收。

## OCI 卸载确认

OCI 卸载在原 image URL 的锁内取得原挂载记录。卸载系统调用成功，或返回后端接受的未挂载错误后，仍须取得已知的挂载表观察，并确认原目标没有挂载。观察失败、未知或仍存在时，保留挂载记录、层引用和链引用；同一进程保存成功卸载标记，阻止新挂载复用该来源，重试仅继续确认。

后续 OCI 层／链引用减少和目录清理尚未具有完整持久步骤；现有错误日志及元数据移除顺序不能证明全部来源资源已结算。该边界必须在发布跨重启物理释放回执前补齐。

## 原物理代际的返回、查询与完成回放

Nydus／S3 挂载返回底层在同一个生命周期锁内捕获的 `physical_generation`。查询请求携带原代际时，只核对原出生记录、原进程和原挂载，不启动程序或重新挂载来源。回复另明确 `released` 和 `release_pending`，供上层继续原清理；它们不表示来源可用于新的运行。来源引用标记更新也比较原代际，迟到的取得确认不能重新打开已经开始清理的同代际标记，旧释放不能清除新代际的标记。

原 `not_started` 登记通过查询返回 `release_pending`；恢复挂载接口只重建原清理绑定，不设置活动来源的引用标记。S3、直接 Nydus 和 OCI 接口的 Nydus 后端都遵守这一行为。恢复或新增清理所有者取得 `release_pending`／`released` 时保留原操作绑定，不写 `ready` 成功确认；独立查询继续读取原物理阶段。活动文件系统恢复拒绝待清理或已释放来源，只有已经授权的原清理可以取得这些结果。挂载未派发的证明仍不等于整个沙箱退役或预算结算。

OCI 接口的持久路由以 schema 1 包装记录及 SHA256，最多 32 KiB；重开拒绝完整性错误、未知或重复字段、尾随数据及未经包装的物理代际声明。原旧路由继续没有物理代际，不自动升级为原挂载证明。活动路由、完成记录与挂载操作合计最多 65536 项，没有自动删除；满额拒绝新记录。发布在同一数据库事务中核对原记录，已完成的原代际不能重新登记。摘要不是签名，也不能隔离完整有效快照回滚。

OCI 接口查询和卸载先查原代际的持久完成记录，再查当前路由。完成回放不查找替代 daemon、不更新其引用标记；数据库重开后仍可回放，即使同一 URL／路径已经出现另一个物理代际。要求原物理身份的新请求必须配置持久路由数据库；普通 OCI 后端暂未具备原物理身份，在创建前拒绝这个请求。它仍是后续开发能力，不能以拒绝代替完成。

## 挂载服务的持久操作和独立查询

S3、直接 Nydus 和 OCI 镜像入口接受调用方预先固定的 `operation_id`，格式为 64 位小写十六进制。镜像服务在任何 daemon 分配前，将 schema 1 操作意图写入同一个持久数据库；完整请求的 SHA256 区分来源、参数、凭据和要求原身份的开关。操作 ID 和恢复使用的原代际选择器不改变原请求指纹。日志只保存指纹和允许的绑定字段，不保存 S3 凭据。OCI 的操作请求必须要求原物理身份，不能回退到未完成归属能力的普通 OCI 后端。

底层在启动进程前将原物理代际、原 daemon ID、实际来源路由和目标路径绑定到原操作，写入失败阻止执行程序。共享已运行来源也必须执行该调用方自己的绑定，不能因 singleflight 合并而跳过。成功确认再次比较原操作、指纹、代际和路径；回复丢失或确认写入失败保留原意图和绑定。相同操作不会再次分配 daemon 或重新解析标签；原意图仍未绑定时返回未解决。

独立的 `POST /mount_operation_query` 以及 `MountOperationService.QueryMountOperation` 以操作 ID 和完整请求指纹查询。它们不派发挂载、不重建路由、不改变引用标记，返回原操作及其原代际的观测。已经绑定但确认没有写入时，可读取原物理状态或原完成回执；原 OCI／Nydus 完成回放先于当前 daemon 查询，来源替换后仍不触碰新引用。三个挂载入口限制请求为 32 KiB，拒绝重复、未知、非标准大小写字段和尾随数据；提供操作 ID 时必须通过格式核验。查询入口限制请求为 1024 字节，客户端限制回复为 32 KiB，并拒绝模糊字段和回复身份变化。

`absent`、`intent` 和 `unresolved` 都不能证明没有派发，也不能授权归还预算。`ready` 是一次原身份的观测，不是未来修改的租约；后续操作仍比较原代际。原启动尚未发布完整出生事实时，查询保持未解决，仍须独立对账与迟到派发隔离。

文件系统管理器使用 schema 5 挂载操作协议 1，把每个原步骤的稳定操作身份传入这一接口；共享缓存命中与根文件系统对象复用也核对各所有者的登记。恢复先查询全部原操作；成功挂载回复丢失或上层确认未写入时，能够取回原绑定而不新建挂载。公共 `QueryOriginalMountOperation` 校验原请求指纹、身份、类别、状态和路径，内存调用也不能跳过校验。无查询扩展的服务在派发前拒绝。上层局部接线不等于未绑定意图、部分启动对账或完整清理已经完成；真实物理故障及整个沙箱预算结算继续单独验收。


## 分配前准备归属与原意图查询

新建 S3／直接 Nydus 挂载，以及 OCI 接口选择的 Nydus 后端，必须使用 `PreparationManager` 能力；托管请求不能回退到没有分配前登记的旧创建接口。原操作 ID 和完整请求指纹从上层一直传到底层，OCI 接口不会被后端请求的新身份替代。准备元数据仍使用严格校验的 schema 1；新增 `preparation` 字段缺省时保留原 schema 1 的摘要兼容。旧严格读取器无法读取含新字段的记录，因此升级必须匹配服务版本，不能退回旧读取器接管新目录。

底层先持久保存原操作、请求指纹、随机物理代际、启动作用域、私有目录计划和父目录出生身份，再要求上层持久绑定同一代际及目标，随后创建 `<image-root>/allocations/<generation>`。该目录的设备号和 inode 在任何子目录效果之前持久保存；默认挂载、daemon、缓存及镜像元数据目录都属于这一个物理代际。调用者指定的目标必须已经存在，仍由调用者持有，清理不删除它。该变化不修改 protobuf，也不自动修改旧记录的资源归属。

准备记录没有发布物理启动意图时，不要求尚未生成的后端配置文件才能恢复。恢复后的准备只允许查询和清理，不自动继续下载、启动或挂载。上层绑定失败后，独立查询通过原操作 ID 和指纹找回同一准备，保留原物理代际；查询不写回上层绑定、不等待在途生产者结束、不登记引用，也不把准备状态宣称为 ready。显式重试可以持久补交原绑定并返回待清理结果。底层没有匹配准备时，上层原意图仍为未知，不能从空库存推出明确未分配。

准备清理先持久发布 releasing，阻止原异步初始化继续派发；在途初始化没有退出时，清理返回未知并保留工作目录。原作用域、父目录出生和私有目录出生必须匹配，目录内仍有挂载时拒绝删除。出生缺失却存在目录、目录被替换、作用域变化及持久发布失败都保留未知，不向邻居发信号或删除替代目录。没有物理启动意图和没有准备目录的原记录可以结清它自己的准备；这是该局部准备的退役证明，不授权归还整个沙箱预算。真实 Start 失败的 `NoDispatchConfirmed` 证明继续由原实际派发失败产生，准备清理不能补造该标志。

初始物理启动沿用分配前已经绑定的代际。进入下载之前、发布物理启动意图时及最终 Start 之前都核验原准备；清理和最终派发共用原物理锁。已释放的代际不能原地重新启动。运行中已有挂载仍按原物理身份绑定共享所有者；旧物理记录保持原校验及结果未知语义。

当前完成记录仍受原来源历史能力限制。源条目及元数据被清理后，没有独立原完成历史的 S3／直接 Nydus 查询仍可能保持未知；本次不把缺失推断为已释放。普通 OCI 原归属、旧记录迁移、完整部分启动出生对账、所有完成历史的安全回收、完整沙箱清理及节点最终预算结算仍需要后续交付。私有文件及数据库回归不替代真实挂载、物理故障或主机故障验收。

## 明确未分配的持久完成记录

沙箱守护进程 sandboxd 的镜像 API（`pkg/imagemanager/api/mount_operation_retirement.go`）提供独立的 `MountOperationRetirementService.RetireMountOperation` 和 `POST /mount_operation_retire`。清理请求只含 `operation_id`、完整 `request_fingerprint`、`kind` 和 OCI 接口的原 `image_url` 四个字段，不传原凭据。HTTP 入口只接受 POST，限制 32 KiB，并拒绝重复、未知、错误大小写和尾随字段。客户端保持原六字段回复校验及 32 KiB 回复限制；不支持这一接口或返回错误时不能回退到无条件清理。

新原生生产者在 schema 1 操作意图中保存 `preparation_protocol=1`；缺省为 0 时保留旧记录及摘要兼容，不能升级旧意图来补造未分配证明。新增字段要求匹配读取器，不能退回旧服务接管新日志。显式清理先取得原操作锁；原生产者仍在工作时立即返回未知。已绑定的原操作继续按原代际查询；底层已经留下原准备时，清理只补交该原绑定并返回其清理状态，不能写成未分配。

原生镜像管理器的 `PreparationRetirementManager.ConfirmNoPreparation` 在根目录所有权内核对全部内存准备、严格磁盘元数据及分配目录。原准备、忙碌的生产者、旧来源没有操作身份、遗漏或损坏的元数据、未知目录和符号链接都会阻止确认。已核实的无关新准备不会被清理，也不阻止原操作的空归属核对。只有新协议的原意图，或尚未到达这个受控原生生产者的操作，才能在核对之后写入 `not_allocated`。新完成记录和原意图在数据库事务内比较并替换；数据库错误、满额和持久写入失败均不产生完成回复。

`not_allocated` 持久绑定原操作、请求指纹、来源类别和 OCI 接口来源，没有物理代际、daemon、实际 Nydus 路由或目标路径。它使原操作的后续 begin、绑定及挂载请求拒绝分配；完整管理器和数据库重开后仍保持屏障。原完成重放不查询替代来源。操作记录、路由及完成历史继续合用原 65536 项上限，不自动删除这个屏障。

独立查询保持只读，`absent`、`intent` 和 `unresolved` 的含义不变。公共清理辅助函数 `RetireOriginalMountOperation` 在请求完成后另行查询并核对同一结果；活动取得不能使用 `not_allocated`。该完成记录只证明这一原挂载操作没有工作目录或物理挂载分配，不证明整个沙箱不存在，也不授权节点归还预算。真实挂载、daemon 故障、完整沙箱清理及节点结算仍须在 BareMetal1 独立验收。

## 调度器管理的直接子进程启动确认候选

具有完整准备操作 ID 和请求指纹的新启动使用 `managed_launch`，保存管理器原会话、不可变清单及其原始字节摘要；没有绑定准备操作的旧启动不升级。清单包含原物理代际、完整程序与 argv 摘要、配置和 bootstrap 摘要、boot／namespace、原根目录、所有权锁、记录目录、目标目录及初始化截止时间。清单及原物理身份在派发前持久保存，清单和后续原事实的完整字节大小均在派发前检查。新增可选字段省略时不改变旧记录摘要；旧严格读取器会拒绝新字段，因此不能降级程序后忽略它。

最终派发在原物理状态锁内重查身份，并把不可变清单、原 flock 的同一打开文件描述副本、原根目录和原记录目录传给直接子进程。新调用移除 `--daemon`，使用四个完整的描述符参数，不等待子进程退出判断初始化成功；再次派发旧意图、所有权会话改变、路径替换、截止时间失效和不匹配的调用都拒绝。父进程在 Start 后关闭自己的传输副本，子进程依照已匹配的 distill-fs 候选契约保留原 flock，直到原挂载事实持久保存或自身退出。父管理器关闭但子进程仍在初始化时，替代管理器不能取得这把锁。

`managed_launch.go` 从原记录目录读取生产端的 `launch-birth-<generation>-process.json` 和 `launch-birth-<generation>-mount.json`。外层保存 payload 原始 UTF-8 字节和摘要，不使用跨语言重新序列化计算摘要；外层及 payload 均拒绝未知、重复和尾随字段，文件必须为 0600、单硬链接、最多 8192 字节的普通文件。消费核对原操作、请求指纹、清单摘要、原命名空间、原进程、内核来源与已有主元数据。原进程与挂载先写成 sandboxd 的不可替换原事实，再持久补交主元数据。管理启动的 PID 来自原记录，不读取 PID 文件补造身份，也不删除意外出现的 PID 文件。

原 ready 需要实际进程及挂载均匹配独立原事实；挂载就绪检查仍须通过。直接子进程只有一个 Wait，原代际和原进程句柄在 Start 的同一临界段登记。清理先持久发布 releasing，再从独立事实持久补交原进程身份，随后才通过完整身份核对和 PID 句柄发送 SIGTERM；有界等待原子进程退出，阻止该初始化继续产生挂载。原子进程退出不能把任意缺失记录变成“未派发”。原第一条记录缺失、损坏、矛盾或持久补交失败仍保持未知占用。

仅在新管理协议中，原进程已经确认退出但首次挂载回执尚未保存时，可以结合此前不可变的生产端进程事实、原清单、已绑定的内核代际来源 `akernel-<generation>`、完整命名空间及唯一挂载 ID 核对尚存的原挂载。原进程仍活动、来源不匹配、原记录目录替换或观察不完整时不采用当前挂载。核对成功先保存不可替换的原挂载事实并提交主元数据，再执行条件卸载；该补交失败时不卸载，重开从原事实继续。旧协议不使用这项来源绑定，不能将当前挂载路径或普通挂载 ID 相等当成归属。

本地复核包含原协议回归、准备后直接启动契约、严格记录、原身份补交、原进程退出后挂载核对、迟到派发拒绝及邻居保护。实际两端非特权用例固定 Rust 候选程序摘要，在受控的无效后端处退出，验证句柄传递、管理器关闭时继承锁仍阻止接管，以及重新取得所有权后消费原进程记录。它没有真实 FUSE、cgroup、网络或模型请求，不替代 BareMetal1 的真实挂载和物理故障验收。

当前候选没有关闭第一条生产端事实缺失的全部结算边界，也没有完成普通 OCI、其他来源完成历史、旧迁移、有界系统调用、全部沙箱清理、节点最终预算结算、独立 Restore 或安全回收。需要匹配生产构建、实际部署字节审计和目标环境故障矩阵，才能标记完整启动及退役闭环通过。

## 整个沙箱退役进度与文件系统完成的区别

条件删除现在在沙箱目录之外保存原元数据、资源租约和逐步完成进度。文件系统释放只是其中一项：运行时不存在、网络断开、ACL、设备、DNAT、资源归还和原目录移除均走过对应确认后，才可保存完整完成回执。原目录移除之前先持久登记该意图，完成回执发布失败后只从原进度恢复，不重复文件系统或运行时清理，也不触碰替代执行。

本地候选仍保留底层完成确认和物理验收缺口。文件系统局部原回执不得被当成整个沙箱退役或中心预算归还证明；缺失进度、损坏、原目录或元数据替换、未完成步骤保持未知。
