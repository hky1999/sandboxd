# 镜像挂载路由与清理失败的原归属保留

沙箱守护进程 sandboxd 的镜像挂载入口（`pkg/imagemanager/api/http.go`）、Nydus／S3 daemon 管理器（`pkg/imagemanager/distillfs/`）和 OCI 镜像管理器（`pkg/imagemanager/oci/`）保留未完成清理的原记录。上层文件系统管理器（`internal/server/fsmanager.go`）的来源登记和完成记录不能补出底层已丢失的路由、PID 或挂载身份；底层错误必须返回给原所有者，不能转换成已经释放的结果。

## 路由发布与移除

配置了持久挂载路由数据库时，`MountOCI` 与 `UnmountOCI` 对同一个原 image URL 串行执行；不同来源分别使用自己的锁。数据库读写错误、缺失路由、未知后端和不完整记录都会返回错误，卸载不会转到另一个后端寻找替代资源。只有原路由明确指定 Nydus 或 OCI，才会调用该后端。

挂载成功后的路由写入失败必须返回错误，不触发内联卸载。上层调用前已经保存的来源意图继续保留，用于对账原调用及其可能的物理副作用。已有路由与新发布的四个字段不同时，原记录继续保留，不能由新的挂载结果覆盖。

卸载后端返回错误时保留原路由。后端成功后，在同一个数据库事务中比较原 `ImageURL`、`MountType`、`NydusImageURL` 和 `MountPoint`，仅移除仍完全匹配的记录；记录变化、损坏或缺失都返回未知错误。这个比较保护路由记录的替换，尚不能区分四个字段相同的两个物理挂载。没有配置路由数据库时保留明确的旧模式；数据库运行中损坏或缺失记录不会进入该模式。

## Nydus 和 S3 daemon 清理

`Unmount` 在 daemon 生命周期锁内设置未确认释放状态。初始化仍在推进、进程报告存活但 PID 无法取得、停止观察超时、卸载失败、挂载回读失败或 PID 文件移除失败，都保留原 PID／登记和未完成状态。新挂载不能复用该 daemon；原所有者可以重试清理。

卸载目标使用内核挂载表的完整目标路径查询，能识别设备编号与父目录相同的 bind mount。未知挂载状态返回错误。成功的卸载系统调用后再次查询挂载表；目标仍存在或观察失败时不清除 PID。当前进程保留成功调用标记，后续重试只确认目标消失，不重复卸载一个随后出现的目标。目标路径必须是绝对规范路径，不能用符号链接充当目标。

只有停止观察、挂载消失与 PID 文件移除均成功，daemon 才进入停止状态并清除未确认释放状态。挂载入口只在成功卸载后清除来源的已引用标记。显式清理、过期清理、失败挂载清理和磁盘压力清理都保留清理失败的 daemon 及其保存文件；挂载确认或目录移除错误不会变成成功清理。

## OCI 卸载确认

OCI 卸载在原 image URL 的锁内取得原挂载记录。卸载系统调用成功，或返回后端接受的未挂载错误后，仍须取得已知的挂载表观察，并确认原目标没有挂载。观察失败、未知或仍存在时，保留挂载记录、层引用和链引用；同一进程保存成功卸载标记，阻止新挂载复用该来源，重试仅继续确认。

后续 OCI 层／链引用减少和目录清理尚未具有完整持久步骤；现有错误日志及元数据移除顺序不能证明全部来源资源已结算。该边界必须在发布跨重启物理释放回执前补齐。

## 尚未完成的物理身份与恢复契约

| 当前实现 | 仍须补齐的条件 |
|---|---|
| 原路由字段比较、同来源串行操作 | 原不可变镜像 digest、唯一挂载登记、底层所有者锁内的条件释放，以及严格记录格式与容量边界。 |
| 卸载后的挂载存在性回读 | 原内核挂载身份、挂载 namespace 和出生来源；存在性及路径相同都不能证明仍是原物理挂载。 |
| 原 PID 记录保留 | 原进程启动时间、程序身份及不受 PID 复用影响的条件操作；缺少 PID 不能证明没有原进程。 |
| 当前进程的未完成与成功卸载标记 | 调用前持久意图、调用后的独立物理回读及跨重启释放回执；进程退出会丢失当前内存标记。 |
| 原所有者重试 | 锁等待、registry 请求、初始化、挂载检查和卸载的 context／deadline 边界，以及成功步骤后持久写入失败的恢复。 |

本地回归使用临时文件、真实路由数据库和可控后端，不执行真实 mount、unmount 或进程信号。真实 FUSE／OCI、daemon 重启及系统调用中断在 BareMetal1 独立环境验收。以上改动不授权调度器归还整个沙箱预算；仍须原操作与物理代际绑定、全部沙箱资源清理及持久退役证明，见 [文件系统归属](scheduler-filesystem-ownership.md) 和 [持久创建操作](scheduler-start-operations.md)。
