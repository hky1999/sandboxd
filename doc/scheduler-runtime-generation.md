# 运行时资源代际的可信接线

服务器传给运行时的 StartConfig.ResourceGeneration 只取自原物理元数据。创建入口、通过创建入口的恢复以及独立恢复入口均重新取值；请求注解、设备提供者注解和源检查点不能成为新物理执行的代际。元数据属于另一沙箱时，在运行时派发前拒绝。没有原元数据的旧输入保持空值，不借用调用方传入的字段。

gVisor 的创建与恢复把这个字段传到同一份 StartArgs，并使用 OCI loader 的 ManagedAnnotations 在请求和设备字段之后写入 akernel.scheduler/resource-generation。空代际覆盖同名外部字段，不能通过伪造注解取得新管理语义。受管理创建先检查完整 bundle 注解、没有已有原生状态，以及私有原目录；返回后再次检查原生状态中的代际、容器 ID、sandbox ID、创建阶段和 bundle 路径。开始运行与恢复读取该状态后，在打开 TAP 或建立控制连接之前拒绝错代际、字段缺失或原 bundle 不符。

原生控制状态最多读取 8 MiB，必须是当前 daemon 所有、没有组或其他用户写权限、单硬链接的普通文件；通过原目录和 O_NOFOLLOW、O_NONBLOCK 读取并核对前后文件及目录身份，拒绝重复字段、尾随内容、FIFO、符号链接、损坏数据和不完整身份。读取器不再凭文件名采用另一个容器或另一个 sandbox 的控制 socket。创建取消在打开输出文件或启动程序之前返回。

受管理创建、开始运行或恢复的结果未知时，适配器不调用旧无条件 runsc delete，也不立即卸载可能仍被原执行使用的私有根目录。创建返回 ErrRuntimeCreationUnconfirmed，恢复返回 ErrRestoreCleanupIncomplete，保留物理意图和上层占用，等待原身份对账。旧没有代际的适配器输入保留原清理路径。

RuntimeGenerationVerifier 是只读拒绝条件。正常删除和失败创建对账在原元数据带代际时，先向实现该接口的运行时核验原生代际；缺失、读取失败或另一代际停止后续删除，不能保存完成或归还资源。永久公开入口用例保留原状态、物理意图、设备租约和创建 PENDING，并证明没有执行修改命令。

受管理创建显式传递 `--scheduler-resource-generation`，要求配套 gVisor 运行时生产版本 1 的出生协议。创建状态同时包含完整资源代际、运行时已派发标志、Sentry 的出生记录，以及需要 gofer 时的独立出生记录。每份记录绑定容器、角色、原 PID、启动时间、初始化进程、实际程序、参数、cgroup 和观察者的启动及 PID namespace；消费者检查结构与对应关系，不把消费字段当作新的实际进程观测。缺少协议或程序不支持参数时保持失败，不退回旧创建语义。

正常删除与失败创建对账通过 `GenerationRuntimeDeleter` 传递原资源代际，调用 `runsc delete --force --expected-resource-generation=<原代际> <完整容器 ID>`。新原生运行时在状态锁内核对归属，取得原进程 pidfd 并确认退出；消费者不把缺失状态、参数不支持或命令失败转换为成功。只有只读核验接口的运行时不能授权无条件删除，配套客户端缺少原生删除接口时也不回退。旧没有资源代际的输入保留既有接口语义。

匹配注解和 PID 数字不能单独证明原进程退出；只读核验不能写成完整退役证书，原生状态缺失不能写成原执行从未存在。原生协议与条件删除的创建进程物理用例不等于完整工作负载生命周期、恢复或预算验收。第一条事实尚未保存的窗口、部分启动、宿主路径与锁的替换、运行时辅助进程、实际 Start 与独立 Restore、完整物理清理及预算仍须分别验收。

永久物理用例 `TestRealNativeCreationBirthConditionalDeletionAndLivePeer` 默认不执行，只有 `SANDBOXD_RUN_NATIVE_BIRTH_INTEGRATION=1` 时启用。必须指定绝对路径 `NATIVE_BIRTH_RUNSC_BINARY`、`NATIVE_BIRTH_ROOTFS`、`NATIVE_BIRTH_EVIDENCE` 和对应 `NATIVE_BIRTH_RUNSC_SHA256`、`NATIVE_BIRTH_ROOTFS_SHA256`；显式启用但前置条件缺失时失败。使用完整配套运行时包，在 BareMetal1 独立容器中创建两个运行时，要求外部观察者先核验四个原进程，随后拒绝错误代际并确认原进程退出及邻居存活。测试另外持有四个原进程 pidfd，独立确认退出，不能仅以状态文件消失判断成功。这个用例不启动应用工作负载、不恢复检查点，也不修改平台节点预算。

gVisor 默认把 gofer 的空网络 namespace 固定在共享运行时根目录的 `null-netns` 挂载点，供后续 gofer 复用。它属于共享根目录生命周期，删除某一个容器不能卸载活动邻居使用的共享缓存。物理用例保存本测试私有根目录及原网络 namespace 的设备号、inode 和句柄，核验两份 gofer 使用相同缓存，并在目标退役后确认邻居与缓存仍保持原身份。只有四个独立 pidfd 确认退出、原生库存为空之后，才通过原目录句柄普通卸载本测试的原缓存，不使用强制或延迟卸载；随后临时目录清理仍须成功。该测试根目录清理不代表平台 daemon 共享缓存、部分启动或其他来源的清理已经验收。

`TestRealNativeWorkloadStartConditionalDeletionAndLivePeer` 使用相同的显式启用及固定输入，但额外在独立容器的私有网络 namespace 中创建两个 TAP，通过实际 `Client.Start` 执行网络设置和开始运行的控制 RPC。两个工作负载分别读取自己的只读导出文件并报告就绪，要求状态为 running、原 Sentry／gofer 出生记录不变。目标退役后邻居仍须运行；最后四个原句柄确认退出、库存为空，再清理原共享缓存及原 TAP。TAP 清理核对网络 namespace、ifindex、名称和 MAC，失败不借用同名设备，也不改原平台网络。该专项仍不提供独立 Restore、完整 sandboxd 资源或节点预算故障证明。

Linux Unix socket 连接地址的路径字段只有 108 字节，直接连接还要保留结束符。较长的控制 socket 路径通过原私有目录句柄和 `/proc/self/fd/<原目录句柄>/<原文件名>` 连接同一个文件，不改变 socket 所在目录或采用其他实例的 endpoint。长路径要求规范绝对路径、私有原目录和普通 socket，连接前后核对原目录与 socket 的设备号、inode 和模式；socket 文件名自身仍超限时明确拒绝。持有目录只解决路径长度及该次连接中的路径核对，不提供运行时生命周期锁或所有控制 RPC 的原进程授权证明；这些边界继续单独验收。

开始运行和独立恢复现在从获取原状态快照起持有配套 gVisor 的 `.lock` 生命周期锁，锁等待受调用方取消、期限和最多 30 秒限制。受管理来源必须有原锁，不能缺失时另建锁；锁文件必须私有、单硬链接且不是软链接或 FIFO。持锁后、建立控制连接前、派发下一条修改 RPC 前和最后状态提交前，重新核对原运行时目录、原锁、原状态文件及原 bundle 的身份和完整字节。控制地址必须是原目录内对应容器的 `runsc-<ID>.sock`，通过原目录句柄连接，并核对连接前后的 socket；读取状态后不再重新借用同名替代文件。

running 状态只修改原状态文件句柄中的根层级 `"created"` 标记，两个原生标记长度相同，其他字节保持不变，包括大于浮点数精确范围的整数和未知字段。使用原句柄而非重新打开路径或替换当前路径，保证最后一刻的路径替换不能把写入导向别人的状态。文件与目录同步后再核对原身份和完整结果；部分写入、同步失败或替换导致结果不明时返回失败，不回滚已经开始运行的执行，也不伪造清理完成。观察者可能在字段写入或故障期间得到不可解析或变化中的状态，应继续保持未知，不能当成不存在或归还预算。生产端出生事实的持久发布仍使用原原子保存流程。

受管理 Start 和 Restore 在打开 TAP 或派发修改 RPC 前，依据已有生产端 Sentry 出生记录取得原 pidfd、原 proc 目录和原程序句柄，核对启动时间、实际程序 SHA256、参数、cgroup、启动标识和观察者 PID namespace。随后启用 SO_PASSCRED，以最多 5 秒的只读 `containerManager.Processes` 查询验证内核 SCM_CREDENTIALS 中的实际响应发送者属于原 Sentry。SO_PEERCRED 可能指向创建监听 socket 的初始化进程，只作为观测记录，不代替实际发送者证明。缺失出生、原进程退出、输入变化或不支持凭据核验的受管理连接保持拒绝，不退回旧控制语义。

同一连接每次读取响应都重新核对内核发送者和原进程存活，不能只验证首字节后允许另一个继承连接的进程补全响应。凭据或辅助数据截断、重复凭据、首字节之后交付文件描述符及超过 8 MiB 的响应保持失败；错误路径关闭已经交付的描述符。原目录、状态、锁和 bundle 的核验继续保留。没有代际的旧输入保留既有接口语义。

永久实际工作负载用例额外将一次连接受控导向本测试的活动邻居，要求只读响应被拒绝且两个原状态和四个原进程保持不变；正确连接保存两个实际发送者的独立证明，再执行既有启动与清理检查。该用例须在指定目标环境显式运行，默认忽略不等于物理通过。本批不增加生产端 socket inode 或 cookie 协议，不证明独立 Restore 的实际工作负载、其他控制 RPC、辅助进程、完整部分启动和原资源对账；普通文件的替换回归也不能替代完整目标环境故障矩阵。

永久用例 `TestRealNativeWorkloadRestoreBirthAndLivePeer` 使用同一显式启用及完整运行时输入，先启动源和邻居，再通过生产检查点处理器生成配对内存／文件系统制品。源 shell 持有随机值并写入沙箱可写文件，检查点后保持运行，随后按原代际删除并通过独立 pidfd 确认退出。新容器使用独立 sandbox ID 和资源代际，在恢复前保存新的 Sentry／gofer 出生，并等待目标 cgroup 外的观察者核验新目标及原邻居。公开 Restore 的旧代际和误连邻居调用须被拒绝；正确恢复后才创建宿主只读导出的探针，要求恢复执行报告原内存随机值和可写文件内容，保存新出生不变及检查点摘要不变的证明。清理新目标后确认两个新句柄退出及邻居继续存活，最后才清理邻居、原共享缓存和三个原 TAP。默认忽略不代表已物理验收，失败保留独立用例。该专项不修改平台预算，不验证较大热内存、跨节点、完整资源清理或恢复失败后的节点结算。

这个配对文件系统专项的源及恢复目标需要实际可写根层，大小上限为 64 MiB，随机值写到该根层的 `/native-memory-token`。原只读根与独立 `/tmp` tmpfs 的物理尝试返回 `no checkpointable filesystems`，尚未进入 Restore；失败保持独立证据，不能改为省略文件系统保存来通过。本用例的邻居及原启动专项仍使用原配置。

固定配套 gVisor 的文件系统制品使用 protobuf 元数据 `fs/fscheckpoint.pb`，同时保存 `multitar.img`、`pages.img` 和 `pages_meta.img`；内存状态为上层 `checkpoint.img`。用例要求实际 protobuf 元数据存在，并核对全部实际普通文件的摘要；不借用旧 JSON 文件名或旧运行时的制品替代。原错误 JSON 文件名断言的物理失败独立保留，配对保存已经返回成功不等于恢复通过。

丢失恢复回复的永久专项复用相同配对制品、新出生、两轮外部核验及邻居保护。只有目标 Restore 请求完整发送后才对原连接执行 `SHUT_RD`，只读鉴权及网络设置不受该故障影响。收到 EOF 后原状态必须仍为 created 且字节不变；实际工作负载可能已经运行，这种已观察到的执行不能被写成收到成功回复。探针核验原内存及根文件，随后只清理原目标代际，错误代际拒绝、六个句柄退出、空库存及原 TAP／共享缓存仍须通过。该真实 socket 故障没有用代理进程转发响应，原发送者核验不降级；普通 socket 测试和默认忽略不能代替目标环境的专项结果。

配套运行时新增 processLaunchVersion=1，分别保存 goferLaunchState 和 sentryLaunchState。not_dispatched 在任何对应派发前持久保存，dispatching 在启动前发布，birth_published 与该生产端出生原子发布。完整控制路径要求 Sentry 出生已经发布及阶段一致；旧完整记录保留原约束，混合阶段或未知版本拒绝。退役的只读核验额外接受 creating 中明确未派发 Sentry 的原准备，或原 gofer 出生已发布的部分状态，必须保留完整代际、私有原状态及对应出生的结构绑定。实际信号和退出确认仍由原生条件删除取得原 pidfd 完成；只读接线和假 PID 数据不证明进程清理。

任一 dispatching 缺少已发布出生继续保持未知，不凭缺少 Sentry 对象补写未派发。完整安装包、实际 gofer 部分启动清理、第一条事实未保存及其他资源完成窗口仍须独立验收，旧当前部署产物不会自动取得这些能力。
# 部分启动的独立物理验收

`TestRealNativePartialGoferBirthRetirementAndLivePeer` 必须显式启用，并在 BareMetal1 的独立容器中使用完整配套运行时和固定根文件系统。测试包装器只跟踪真实 runsc 创建进程，在原状态目录的 `fsync` 实际返回成功、gofer 出生已经发布且 Sentry 尚未派发时暂停创建进程；包装器和测试均不补写出生状态。目标 cgroup 外的观察者核验创建进程和三个原子进程的 PID、启动时间、程序摘要及归属，再通过原 pidfd 终止创建进程，之后才授权条件删除。测试分别检查创建没有成功回复、原状态字节保持、错误代际拒绝、原 gofer 退出、邻居工作负载存活及最终库存和测试资源清理。默认忽略此入口不代表物理通过；该用例不覆盖第一条出生记录缺失、完整 daemon 资源或节点预算。
