# 调度器的文件系统归属与分步释放

沙箱守护进程 sandboxd 的文件系统管理器（`internal/server/fsmanager.go`）在任何根文件系统或额外挂载调用前，先把 sandbox ID、原资源代际、根文件系统来源和全部 S3／OCI 来源写入持久数据库的 `config.SandboxFSStateBucket`。数据库只包含恢复挂载所需的来源，不保存创建请求中的命令或环境变量；来源可能包含 S3 挂载凭据，数据库必须位于 daemon 的私有持久目录，不能导出到源码仓库、命令输出或实验日志。

准备失败返回原部分准备对象，保留已取得的引用和全部来源，不自行回滚。提交写入失败继续保留进程内登记和此前的持久意图，不以错误返回推断数据库没有改变。共享创建流程停止后续运行时启动；已有物理意图及 ID 继续由原代际对账。

## 日志完整性与升级

每个活动登记在首次写入前保存原 sandbox ID、资源代际和全部来源的 SHA256；推进阶段不会重新生成这份原来源摘要。整个日志另有覆盖 schema、活动登记、阶段和完成记录的 SHA256。写入前验证原来源，重开先验证完整日志，再接收任何登记或调用挂载后端。来源、身份、步骤或回执变化，以及未知字段、重复 JSON 字段、来源类型与实际字段不匹配，都保持原始日志并阻止恢复、释放和新分配；关闭过程也不覆盖损坏日志。错误信息不包含来源数据或 S3 凭据。

schema 0 只接受原来的 `items` 及 `rootfs`、`s3`、`oci` 来源字段，可以迁移到 schema 5 并重建旧引用，但资源代际继续为空。即使为空，混入新归属或阶段字段也会拒绝。非空 schema 2 没有原活动来源和阶段的完整性证明，不自动补摘要来宣称原归属已验证；需要独立迁移证明，或先使用匹配旧程序完成清理。空 schema 2 可以升级。非空 schema 3 没有底层原挂载代际，不能从当前来源补出原身份，需要独立迁移或由匹配旧程序先完成清理；具有正确原完整性摘要的空 schema 3 可以升级。上一个 schema 2 源码候选没有部署，升级前仍须核对目标数据库，不能仅凭本地测试假设库存为空。

schema 4 必须先通过原完整性与严格字段校验；已有原物理代际原样保留，操作协议保持 0，不为旧所有者生成此前不存在的挂载操作身份。schema 4 即使混入值为零或 false 的新操作／清理字段，也会拒绝。缺少原取得确认的旧登记继续未知，不能从当前来源或新日志补造原操作。

这些摘要用于发现 daemon 私有日志的损坏或意外修改，不是签名，也不能发现整份日志被回滚到过去的一份有效快照。旧格式迁移不会补出此前不存在的来源完整性证明。这些条件不代替不可变镜像 digest、实际挂载身份或全部资源退役确认。

## 每项来源的持久状态

日志 schema 为 5。根文件系统和每项额外挂载分别记录下列状态；同一管理器串行推进所有权、引用变更和持久写入。

| 状态 | 含义和推进条件 |
|---|---|
| `reserved` | 原来源已登记，尚未派发挂载调用。取消这项预留不调用卸载，也不减少其他所有者的引用。 |
| `acquiring` | 挂载调用前的意图已写入；调用或确认可能中断，不能从错误或缺少进程内引用推断没有副作用。 |
| `acquired` | 当前进程已经取得该所有者的引用，并保存底层在同一挂载操作中返回的原物理代际，随后持久写入。 |
| `release_pending` | 减少引用或卸载前的意图已持久写入；错误保留引用与来源。 |
| `released` | 当前所有者的引用已经减少，或者最后一次卸载调用成功；确认已写入后，后续重试跳过这一项。 |

新建且具有资源代际的所有者使用挂载操作协议 1，并要求持久文件系统数据库和支持独立操作查询的镜像服务；缺失任一条件，在登记或派发前拒绝。根文件系统及每项来源按原来源摘要、步骤用途和有序来源下标分别固定操作 ID。操作 ID 是 `json.Marshal` 编码的四字段对象（`Domain`、`Owner`、`Purpose`、`Index`）的 SHA256 小写十六进制；`Domain` 固定为 `akernel-filesystem-mount-operation-v1`，`Owner` 为原来源摘要，`Purpose` 为 `rootfs`、`s3` 或 `oci`，根文件系统下标为 0。协议 1 的编码不随升级改变；完整意图先写盘，再传递操作 ID。不同所有者、不同步骤及重复来源的不同下标都有自己的记录。共享缓存命中仍登记并独立核对原操作，根文件系统对象的缓存键也包含操作身份，物理来源继续共用同一引用管理器。本地根文件系统不调用镜像操作服务。

原清理开始前保存单调的 `release_requested`，不能改回 false，操作协议也不能更改。该字段只授权原所有者继续清理，不表示整个沙箱已经退役。

最后一个引用的卸载失败不会删除缓存或减少引用。根文件系统与额外挂载共用 S3／OCI 来源的引用管理，避免两套管理器分别以为自己持有最后一个引用。卸载结果未确认的来源进入隔离，新准备对象可以记录预留，但不能派发使用该来源的挂载；取消这个新预留不会消费原所有者的引用。原清理可继续重试。

物理步骤成功但随后写入失败时，进程内保留已经完成的阶段；下一次推进先写入这些确认，再进行任何新引用或释放，避免同一进程重复减少共享引用。所有阶段完成后，活动登记与绑定原 sandbox ID、资源代际及来源 SHA256 的文件系统完成记录在一次数据库事务内交替。完成记录写入失败仍保留全部已释放阶段，重试只补最终记录。

`ReleaseIfGeneration` 要求原代际。有匹配文件系统完成记录时只回放原完成，即使同一 ID 已属于替代执行也不修改它；没有活动归属或完成记录时返回未知，不能从缺失推断成功。无条件 `Release` 拒绝有代际归属的登记。已完成的非空资源代际不能再次分配。符合原格式的 schema 0 来源可用于恢复旧引用，但缺少代际的记录不能借用当前元数据的代际；升级条件见上文。

活动登记与文件系统完成记录合计上限为 65536 项，满额拒绝新分配，没有自动删除。安全归档、字节容量边界和空间回收仍待开发。daemon 关闭保留失败及未完成登记；不能通过清空文件系统状态制造清理成功。

## 重开与启动保护

在任何引用重建或孤立登记清理前，恢复流程核对所有已发布物理记录和创建意图的文件系统归属。缺失登记、代际变化或已发布执行具有未完成的文件系统清理都会阻止恢复就绪，避免少算一个现存实例的共享引用。原创建意图可以继续原代际的清理；完成文件系统记录不能冒充整个执行已退役。

具有资源代际的登记在恢复前核对整份库存的原底层绑定。协议 1 的每个尚需引用步骤，使用原操作 ID 与完整原请求指纹查询镜像服务，核对操作身份、来源类别、完整物理代际、目标路径和状态。原确认缺失时只接受该原操作的确定绑定，先持久保存，再重建引用；已有绑定不能改变。先验证全部所有者，再重建任何共享引用。查询错误、错误身份、`absent`、`intent` 和 `unresolved` 不授权重新派发或释放。恢复调用带原代际及同一操作 ID，只回读原资源；挂载回复还须与独立查询的原绑定一致。只有已经持久请求清理的所有者或 `release_pending` 步骤，可以重建已释放或正在释放的原来源用于继续清理；活动所有者不能把它当作可运行的文件系统。恢复先固定孤立所有者的清理意图，再重建引用和继续释放。协议 0 的旧有代际取得若缺少确认，继续返回未解决，不按 URL 派发新的挂载调用。已释放阶段不重新取得。明确的旧无代际模式保留旧来源恢复路径，不转为有代际归属证明。所有原登记的剩余引用重建完成后，才允许清理没有物理记录的孤立登记。恢复错误保留完整来源和此前成功重建的引用，后续恢复不会再次取得已经保留的同一引用。

Nydus／S3 底层持久保存原进程、boot／namespace、内核唯一挂载身份及释放阶段，镜像入口在生命周期锁内取得原代际，上层日志保存根文件系统及每项 S3／OCI 接口来源的原底层代际，见 [镜像挂载释放边界](scheduler-image-mount-release.md)。根文件系统对象同时保存该返回身份；最后一个引用释放携带它，额外挂载在任何引用减少前比较原代际。已知绑定不可重写或清空。要求原物理身份的 OCI 接口请求目前只支持其 Nydus 后端，普通 OCI 后端在物理创建前拒绝，不能无条件回退。不可变镜像 digest、OCI 原挂载身份、完整跨重启回执历史、有界调用、旧登记迁移及跨主机故障范围仍须补齐并在固定部署上验收。可变镜像标签不能代替原挂载的不可变身份。根文件系统来源与恢复使用的本地路径必须继续可用。

## 验收与证明边界

本地回归使用真实数据库重开及可控挂载后端，覆盖日志来源／身份／阶段／回执变化、重复字段、严格旧格式迁移、缺少来源摘要的 schema 2 拒绝、无效来源在任何重建前拒绝，以及准备／提交失败、卸载错误、步骤确认与最终完成写入失败、部分释放后重开、并发重复释放、S3 与 OCI 的共享引用、旧代际回放、损坏日志和启动前归属缺失。系统调用、真实挂载及 daemon 崩溃的物理验收在 BareMetal1 的独立环境另行进行。

文件系统完成记录只证明这一管理器的资源步骤。调度器归还预算仍需要原操作、完整物理身份，以及运行时、网络、设备、cgroup 和根目录全部清理后的沙箱退役证明，见 [持久创建操作](scheduler-start-operations.md) 和 [资源租约](scheduler-resource-leases.md)。

本管理器已接通每个原来源步骤的稳定操作身份、共享所有者登记与独立查询，见 [挂载服务契约](scheduler-image-mount-release.md)。本地回归覆盖成功挂载回复丢失、上层确认写入失败后的原绑定恢复、S3 和重复来源步骤、完整库存查询、错误身份及未知状态、旧 schema 4 升级和清理意图单调性。未绑定操作意图、尚未发布完整出生事实的部分启动、迟到派发隔离、普通 OCI、换代或删除后的完整回执历史、有界调用和独立旧登记迁移仍须完成；旧代际已完成与同 URL 新代际活动所有者同时存在时，当前单来源缓存仍须完善恢复处理，不能把隔离视为最终对账。底层完成记录只用于继续该来源的原清理，上层文件系统完成仍不授权整个沙箱预算归还。
