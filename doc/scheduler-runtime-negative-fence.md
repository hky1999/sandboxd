# 缺失创建意图的Runtime持久负向围栏

调度器在本地创建日志缺失时不能根据空库存释放预算。`GetStartOperationRequest`的`seal_runtime`扩展只接受完整`history_identity`、`seal_missing=true`和已经过期的原查询截止时间。操作编号仍通过完整历史身份和请求指纹确定；调用不发起创建。

服务在创建准入互斥锁内检查最多4096个已登记操作。任何记录缺失、损坏或存在同Runtime的其他操作均拒绝负向结算。完整物理准备库存及所有配置原生运行时库存必须为空，恢复门必须开启；物理锁和原元数据不存在证明与原持久索引共同保护发布。成功后保存`runtime_sealed`事实，响应携带`runtime_fenced=true`和`NOT_CREATED`。后续同一Runtime的任何请求指纹都在准入时拒绝，原请求回读复用同一事实。目录、索引、不可变意图或结果损坏不产生成功回执。

按单个操作编号封禁的旧接口语义保持。它的回执不会自动升级为Runtime围栏。新的Runtime围栏可随已关闭分配的既有CollectHistory握手回收；历史边界仍阻止该分配再次准入。已有操作、其他Runtime和其他物理代际不由本接口删除或回收。接口属于受信任的本地控制socket，不代表任意外部任务可自行决定预算归还。

匹配的节点必须先持久登记负向查询意图，重开复用原操作编号、指纹、身份与期限。确认缺失或传输结果未知时继续保留预算，不能重试物理创建来猜测状态。构建与组件测试和BareMetal1物理故障验收分别记录。
