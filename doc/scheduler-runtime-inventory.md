# 运行时清单的完整观察

固定 gVisor 源码的 `runsc list` 会在加载容器状态失败时打印警告并跳过该项，因此命令成功及空 JSON 列表不能单独证明运行时不存在。`pkg/runtime/runsc/client.go` 在命令前后通过同一个原目录句柄独立枚举本地 `.state` 文件；CLI 继承该目录句柄并使用 `/proc/self/fd/3`，路径切换不能将命令导向另一目录。结束后重新核对目录、文件名、设备号、inode、大小和完整文件摘要，清单中的每个容器必须与原状态逐项对应。

枚举最多读取 131072 个目录条目，每个状态文件最多 8 MiB，CLI 输出最多 16 MiB；`io.Copy` 同样经过输出限额，不能借用内嵌 buffer 的方法绕过限制。状态通过原目录内的 `O_NOFOLLOW`、`O_NONBLOCK` 读取，必须为当前观察者所有、单硬链接且没有组或其他用户写权限的普通文件。缺失、损坏、重复 JSON 字段、尾随内容、FIFO、符号链接、原身份不匹配、列表遗漏或多报、目录或文件变化均返回错误，不返回一份空清单。原目录不存在也不能被补造为新目录。空目录枚举正常结束时的 EOF 与读取失败分开处理。

运行中、已创建及已暂停的 CLI 状态要求 PID 和状态与原文件一致；上游可能在内存中观察停止而没有重写原文件，因此已停止状态允许没有活动 PID，但该实例仍在清单中。这项核对只证明当前清单没有遗漏本地状态文件。读取期间固定的目录身份不是持久运行时出生身份，PID 数字一致也不是进程出生证明；尚未留下状态文件的初始化、运行时原出生、控制句柄及原代际条件删除继续需要独立实现和验收。现有记录目录为空不能证明没有未记录的进程。

公开条件删除的本地专项使用真实 runsc 适配器、原文件读取器和私有状态文件，以及受控 CLI 的遗漏回复。它要求在任何运行时修改命令之前拒绝清理，保留原目录、意图、设备租约和创建 PENDING；该专项不启动实际沙箱、cgroup、挂载或模型调用。`TestRunscListRealBinaryHeldRootAndCorruptInventory` 默认跳过，只有在指定物理主机的独立受限容器中显式设置 `SANDBOXD_RUN_RUNSC_INVENTORY_INTEGRATION=1`、实际绝对程序路径 `RUNSC_INVENTORY_TEST_BINARY` 及完整 SHA256 `RUNSC_INVENTORY_TEST_BINARY_SHA256` 才运行。它只检查私有空目录、上游跳过损坏文件的实际行为及新读取器的拒绝；未提供必要条件时失败，不跳过。
