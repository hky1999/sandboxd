# 调度器资源租约与准备失败的归属

沙箱的资源代际独立于资源池的物理名称。池化 cgroup 的路径、网络端点的 IP 和 ifindex 在再次租用后可能保持相同，旧清理操作不能依据这些值释放新所有者。本契约规定守护进程的租约条件与持久回收；调度器仍须另外核对原操作、sandbox ID 和资源代际，以及完整沙箱退役证明，才能归还预算。

## cgroup 的物理代际所有权

`CgroupManager.AllocateForGeneration` 在交付前捕获原目录的设备号／inode、启动标识、cgroup／mount／PID namespace 和挂载根身份，与原路径和资源代际一起写入 `config.CgroupBucket`，确认持久写入后再次核对原身份才成功返回。身份读取或持久写入失败返回原路径和错误，租约继续占用，不进入空闲池；不能在回收时采用后来同名目录的身份。共享创建流程记录这个已知路径，不把错误解释为没有分配。

`RecycleForGeneration` 要求原路径、资源代际、分配时目录身份和观察环境匹配，并在清理每一步之前及结束后复核；没有匹配的活动所有权或完成记录时返回 `FailedPrecondition`。身份缺失、同名目录替换、启动／namespace／挂载根变化及清理途中来源改变时停止后续步骤并保留占用，不发布完成。清理成功后，将活动租约移除及原代际完成记录写入同一事务，再允许路径回到空闲池。写入失败继续保留原活动租约。重复回收仅回放同一路径的原完成记录，即使路径已租给邻居，也不再次清理物理资源。无条件 `Recycle` 拒绝有代际所有权的租约。当前清理动作仍有路径接口；此复核不代替后续基于原目录句柄的执行、持久关闭和重启恢复。

新日志 schema 为 4，记录活动路径、路径到代际的所有权、原目录／观察环境绑定及代际到原回收路径的完成记录。重启拒绝未知 schema、绑定矛盾、重复代际、同时活动与完成的代际，以及不属于本管理器的路径。原 schema 2 的完成记录保持原重放语义；缺少原目录绑定的活动所有权保留且拒绝条件回收，不从当前同名目录补造身份。旧没有所有权的活动租约保持未归属，不自动借用当前沙箱的代际。升级前必须在旧匹配程序上确认本任务原执行与租约已经清理，或者开发独立的可证明归属迁移；不得清空数据库来绕过它。

活动所有权与完成记录合计最多 65536 项。满额拒绝新的代际分配，没有自动删除或过期回收。安全归档与容量回收仍待实现。

## 池化网络端点的每次租用身份

每次池化网络分配生成新的 UUID `NetResource.leaseID`，将完整序列化事实作为活动键，写入 `config.BridgeIpBucket` 后才成功交付。重启保留原活动身份，不按 IP 或 ifindex 重建一个新的身份。

池化 `Recycle` 在设备确认断开后，将活动键移除及原 leaseID 对完整原始序列化事实的 SHA256 完成记录写入同一事务，随后清除空闲条目的 leaseID 并允许复用。持久写入失败时保留原活动键，禁止加入空闲池。原租约的重复回收、断开或丢弃可以回读精确完成记录，不能匹配新所有者的活动键；活动记录缺失且没有原完成记录时返回 `FailedPrecondition`，任何变化的事实也不能借用完成记录。

网络租约日志 schema 为 2，活动键与池化完成记录合计最多 65536 项，没有自动删除。启动前校验 schema、UUID、指纹、重复活动身份及活动与完成的冲突。既有不带 leaseID 的活动资源维持旧的未归属语义，不能冒充新租约的完成证明。`Discard` 的完整销毁证明、临时 veth 与 namespace 的逐步清理及崩溃恢复仍待补齐；本契约不将这些路径写成已经完整验收。

## 设备租约的资源代际与独立完成

`xpumanager.NewWithStore` 在原节点状态存储的 `scheduler-xpu-generation-leases` 中持久保存设备子请求原字节及指纹、sandbox ID、资源代际、设备编号与 UUID、准备意图、已确认分配和完成。共享创建流程在初始物理元数据及上层绑定保存之后、并行文件系统和网络准备之前调用 `AcquireForGeneration`；CPU-only 请求也保存明确的空设备所有权。设备子请求指纹不替代上层创建操作 ID 和完整请求指纹，退役进度仍持有完整原元数据。写前意图阻止迟到的原分配在清理后重新生效；设备所有权持久保存并回读通过后才交付 OCI 修改。

独立的 `<RootDir>/scheduler-xpu-leases` 使用 0700 目录和 0600 原 flock，核验目录及锁的内核身份。初始化保存随机日志身份、目录出生身份和 pending／complete 状态；只有完整初始化保存后才可交付管理器。节点日志绑定这个原身份。已初始化的数据缺失、旧目录没有初始化、借用另一目录的记录、记录变化或格式损坏都拒绝自动建立空池，不能把丢失状态当成设备空闲。未完成的首次初始化仅可从原 pending 及空日志继续。严格读取拒绝未知、重复、缺失、尾随或非规范编码，日志不超过 64 MiB，活动及完成记录合计不超过 65536 项，没有自动回收完成历史。

`ReleaseIfGeneration` 要求原 sandbox ID 和资源代际。它在调用方已确认运行时不存在之后，保存并回读同一原设备租约的完成，再释放内存中的分配；写入或回读失败保持未知，不能交付设备给另一请求。数据库已提交但确认读取失败时，原管理器保持占用并拒绝继续修改，重开从原日志恢复；原完成重放不修改同 ID 的新代际或另一个设备所有者。`ConfirmReleasedForGeneration` 独立读取原完成；缺少原记录或只有当前空库存不构成证明。旧无条件释放不能清理仍有活动代际的设备租约。

正常条件删除和失败创建清理均不回退到旧设备接口。只有独立完成读取通过才保存 `devices` 进度。新退役进度在出生时登记 `device_protocol=1`，原目录删除后重建整个完成回执仍要求原设备完成；缺省为 0 的旧进度只能保留为未知，不能升级旧的无条件设备步骤来补造确认。已经持久发布的完整退役回执保留既有重放语义。这项新字段要求匹配严格读取器，不能降级程序后忽略它。

旧 OCI 设备注解只有 sandbox ID 时继续作为未归属占用，不借用当前资源代际；新的代际注解必须与独立日志一致，残留的已释放注解不能重新激活租约。该能力证明设备分配账本的归属与完成，不证明 NVIDIA 驱动上下文、GPU 执行、GPU 检查点或恢复已经物理验收。设备发现失败的 CPU-only 节点仍可登记空租约；有活动设备而原库存无法核验时拒绝启动管理器。目标环境的匹配构建、部署字节及设备故障矩阵仍需独立完成。

## 部分准备失败

资源准备函数收集全部结果并按声明顺序返回错误，同时返回所有非空的已知租约，包括带错误的已知租约。该函数不自行回收资源。共享创建流程将部分资源事实写入原 INTENT 元数据；成功准备的文件系统登记原来源；随后保留物理意图、资源和已预留 ID，等待原代际的权威对账。

第一次物理元数据发布尝试之后，共享创建的全部错误路径保留现有原归属，包含运行时已经成功后的端口规则、提交或可见发布错误。初始发布可能已 rename 而目录同步报错，因此也保留预留 ID，不把错误解释为没有写入。物理意图对账在运行时不存在得到确认后，先断开已知原网络租约，再移除 ACL；任何错误都阻止后续资源回收。已提交但未发布的物理记录继续由原创建结果查询核对，不在失败返回路径上改写或删除。

文件系统从挂载调用前登记原来源和代际；准备／提交失败保留原归属，每项释放记录进行中与完成，根文件系统与额外挂载共用来源引用。旧代际回放不再次减少替代执行的引用；缺失完成记录拒绝成功。完整契约和物理身份限制见 [文件系统归属](scheduler-filesystem-ownership.md)。

一般 cgroup 和网络分配生效到父元数据记录之间的窗口、完全未知的分配、镜像管理器原挂载的不可变物理身份和卸载回读、其他资源的逐步清理及目录删除确认，以及清理完成到沙箱退役回执发布之间的窗口仍待完成。文件系统或资源池完成记录不是整个沙箱的完成退役回执。

本批验收范围是本地组件测试、实际数据库重开、代际条件和持久写入失败；真实宿主上的部署字节与故障矩阵仍须在 BareMetal1 单独验收。
