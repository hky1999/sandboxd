# 调度器的持久创建操作

调度器使用独立的 `StartOperation` 和 `GetStartOperation` RPC。旧 `Start` 保留既有语义；新客户端不能回退到旧接口。创建请求包含非零规范 UUID、调用方的完整请求 SHA256 和绝对截止时间。sandboxd 另行对完整嵌套 protobuf 请求计算确定性 SHA256，拒绝同一已准入操作的请求内容、指纹或截止时间变化。日志只保存摘要及物理结果，不保存环境变量、凭据、命令内容或错误消息。

服务端在派发前登记操作，并绑定 `sbox-<operation_id>` 和独立生成的资源代际。调用方不能选择物理 ID 或资源代际。创建执行使用 daemon 生命周期上下文和原截止时间，RPC 调用方取消不会删除意图或丢弃最终结果。重复已准入请求只查询原结果，不执行第二次创建。

`<RootDir>/scheduler-start-operations` 是模式 0700 的私有目录，每项操作具有不可变 `.intent.json` 和可更新 `.json` 结果文件，模式均为 0600。独立的 `<RootDir>/scheduler-start-operations.index` 持久记录已准入操作 ID，模式为 0600；先同步索引，再发布意图及结果。文件先同步再发布，目录也同步。稳定 `.lock` 文件持有独占 flock；目录或索引被替换、丢失、截断，以及任一已准入操作丢失两份文件，均不能使操作重新成为可派发请求。目录总条目上限为 65536；记录上限为 64 KiB，索引也有独立字节上限，没有自动垃圾回收。

| 结果 | 客户端可以据此做什么 |
|---|---|
| `UNKNOWN` | 没有最终证明，继续保留占用。空库存和截止时间经过均不能单独结算。 |
| `PENDING` | 操作已准入但结果未最终确认，继续对账，不能重复创建。 |
| `STARTED` | 返回历史创建结果及原始物理身份，供按代际清理使用；不证明当前仍在运行。 |
| `NOT_CREATED` | 操作在物理副作用前被持久拒绝，或缺失操作已被持久封住；核对库存后可以结算原预留。 |
| `RETIRED` | 只有原 sandbox ID 和资源代际的完成退役回执才授权此结果；客户端继续按原身份回放条件删除回执。 |

调用方显式设置查询的 `seal_missing` 时，服务端仅在原截止时间已过、准入索引健康且操作从未准入的情况下尝试封住操作。发布前持有物理锁，核对已发布记录、物理意图、磁盘目录及全部已配置运行时的物理列表；未知、恢复未完成或发现相应物理执行时拒绝结算。封住之后，所有迟到 `StartOperation` 都被拒绝，最终结果可以查询。使用旧 `Start` 的未知操作不具备这个迟到请求屏障，客户端不得为其设置 `seal_missing`。

守护进程在提交物理创建后、提交最终操作结果前崩溃时，查询可以从原执行恢复历史 `STARTED` 结果。物理恢复必须完成；服务端在物理锁下核对已提交元数据中的原操作 ID、sandbox ID 和资源代际，执行最长 5 秒的运行时 List 查询，要求唯一且正在运行的原执行，读取原网络资源事实和端口，再次核对完整元数据未变化。缺少匹配事实时仍为 `PENDING`；观测失败、元数据在查询期间变化或持久发布失败时返回 `Unavailable`。结果写入原操作日志后才返回成功，后续查询直接回放历史结果，不重新借用当前执行的身份。历史创建结果不授权预算归还，也不保证查询之后执行仍然存活；预算结算仍要求精确退役证明。本地回归覆盖重开、持久回放和事实变化，真实守护进程崩溃故障尚待部署验收。

运行时 Start 或 Restore 已调用而返回错误时，共享创建流程保留物理意图、资源租约和已预留的 ID；调用错误不能证明执行从未出现。错误包含 `ErrRuntimeCreationUnconfirmed`，既有 `ErrRestoreCleanupIncomplete` 同样保留。启动对账或显式恢复重试清理意图时，先取得物理锁，再核对磁盘中的完整原始 INTENT 元数据。读取元数据要求非符号链接的普通文件且不超过 4 MiB；任何不完整、已提交、已发布或变化的身份均拒绝清理。运行时库存不得含未知条目或重复目标；Delete 或准备状态清理之后还须回读目标不存在并复核原身份，才能进入资源回收。这些本地身份条件不构成失败创建的完成退役回执。

资源准备失败时，准备函数将所有已知租约交回共享创建流程，不自行回滚；共享流程登记部分资源事实和成功准备的文件系统来源，保留原 INTENT、资源与预留 ID。cgroup 分配和回收绑定原物理代际，池化网络端点每次租用具有新的身份；资源回收完成记录确认持久写入后才允许复用，旧重试不清理邻居。完整条件及证明边界见 [资源租约契约](scheduler-resource-leases.md)。

物理副作用后的失败继续保留 `PENDING`，除非获得精确完成的沙箱退役回执。失败创建的完整物理清理证明仍未实现，包括分配生效到归属登记的崩溃窗口、完全未知的分配、文件系统准备／提交错误、全部资源的逐步清理、目录删除确认和清理完成到回执发布之间的崩溃窗口；本接口不能把资源池完成记录、清理日志或记录缺失当成整个沙箱退役。独立 `Restore` 的持久操作整合、统一预算和物理故障矩阵也未完成。
